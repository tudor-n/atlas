## Design system (wave A)
- **N2 The `@font-face` families are named "Roboto" and "Roboto Mono"**, not fontsource's "Roboto Variable", so the design's font stacks reach the bundled files. An installed Roboto is shadowed by them, so every machine renders the same. The `unicode-range` of each subset is fontsource's own. Italic isn't bundled: the browser slants the upright font for the rare `<em>`.
- **N3 `nav-model.parseHash` returns `{name, params, param, query}`.** `params` (the whole list, as `app.js` passes to `render`) stays next to the brief's `param` (its first entry, or null), so wave B can switch over without changing any view. A malformed escape (`%E0`) is kept as typed instead of throwing: `app.js` threw `URIError` and the route died. A node test compares the result with `app.js`'s own `parseHash` while that still exists, and skips once wave B removes it.
- **N4 `nav-model` extras:** `tabByKey` (Alt+1…6, Alt+0), `SETTINGS_SECTIONS` with their rail labels, `SETTINGS_DEFAULT`. `settingsSection` ignores case. `browseTarget` accepts `deadlines`, `people` and `project/<slug>` (the server's `[a-z0-9-]+`); anything else gives `deadlines`.
- **N5 The status cluster's chips come in a fixed order:** `OFFLINE`, then `READ-ONLY` or `DRIVE` (a read-only root is also a drive state, so it shows once), then `N FAILED`. Each chip carries a `title` (the drive text, the read-only reason, the count). `opts.drive` overrides the summary's (the shell's `/api/state` is fresher). Usage falls back to `7D` when the 5-hour window has no reading, as the widget tile does. `agents.text` is `2 RUNNING · 1 WAITING` (the waiting part only when above 0). `voice` is `widgetVoice()` plus `on`. `widget-model.js` now exports `usageWindow`; nothing else there changed.
- **N6 `press.js` slide-off uses a delegated `pointerout`** (`pointerleave` doesn't bubble), and the press is released on any `pointerup`/`pointercancel`, window blur or a hidden tab. `twice()` puts back the button's own child nodes, not only its text, and announces "TAP AGAIN: <button name>" in a visually hidden `aria-live` region (`.sr`). Keyboard activation goes through `click`, so Enter and Space confirm too.
- **N7 Fields are 48px by default** (the arm's `.fld`); `.h40` and `.h52` size inputs and selects too. A focused field shows a white border and no outline, since the border is the focus mark; every other control gets the 2px white `:focus-visible` outline. A bare `<button>` has no look of its own: `.b`, `.row`, `.tab`, `.seg` and `.swb` give it one.
- **N8 The switch is `button.swb[role=switch][aria-checked] > span.sw > i`**, with the optional label inside the button (the whole block is the hit area, like the arm's LIVE); the arm's `.on > .sw` form works too. A disabled switch is a black track with a grey knob. `prefers-reduced-motion` removes the knob's 120 ms slide. Primary buttons keep the arm's weight 700.
- **N9 List rows carry white 15px text**, not the arm's dim 14px: the arm's list is a calibration checklist, ATLAS's rows are content. A dot inside a row drops its own margin (the row's 12px gap spaces it, as the arm's 20/40px offsets do). Desktop hover darkens a pressable row to `#141414`.
- **N10 A few helpers beyond the brief**, all from the arm: `.sq` (the 6×6 square), `.dl` (dot plus mono 12 dim text), `.hn`, `.d`, `.f`, `.amb`, the hairline rules `.bl/.br/.bt/.bb`, `.row .grow` and `.row .sb`, and a `meter()` builder for `.meter4` (3px gaps, the arm's 37px-on-40px pitch).
- **N11 The guard test** (`tests/test_web_design.py`) scans `web/css/**`, `web/widget.css` and `desktop/dist/*.html` (their `<style>` blocks and any `style=""`). `widget.css` is an expected failure (non-strict xfail, `LEGACY` in the test) until the widget is restyled; drop it from `LEGACY` then. `style.css` isn't scanned: wave B removes it. Beyond the brief it also refuses 4- and 8-digit hex (alpha), named colours, `opacity` below 1, `@keyframes`/`animation`, `@import`, protocol-relative `url(//…)` and `setAttribute('style', …)` in JS.

## Shell
- **S1 `open_main` is declared through the app manifest** (tauri-build 2.7.3): `build.rs` calls `tauri_build::try_build(tauri_build::Attributes::new().app_manifest(tauri_build::AppManifest::new().commands(&["open_main"])))`. The build writes the generated `allow-open-main`/`deny-open-main` to `src-tauri/permissions/autogenerated/open_main.toml`; that folder is git-ignored (`app/desktop/.gitignore`, like `gen/`), so a build in the live copy never leaves an untracked file behind. With an app manifest, tauri 2.12.4 checks every app command against the ACL, so the main window (no capability) is refused; only `capabilities/widget.json` grants `allow-open-main`. That capability keeps tauri's default `local: true`, so the widget's starting page (`dist/index.html`, which has no script) could call it too; a separate remote-only capability wasn't worth it, since that page needs `allow-start-dragging` anyway.
- **S2 Black from the first frame:** `WebviewWindowBuilder::background_color(tauri::window::Color(0, 0, 0, 255))` (it sets both the window and the web view) and `.theme(Some(tauri::Theme::Dark))`, both in the locked tauri 2.12.4, plus the black `main.html`.
- **S3 Window state** (tauri-plugin-window-state 2.5.0): `Builder::default().with_state_flags(POSITION | SIZE | MAXIMIZED).skip_initial_state("widget")`, then `widget.restore_state(StateFlags::POSITION)` (the plugin's `WindowExt`) in setup, right after the widget is built and before the work-area clamp. The flags are global to the plugin, so `.window-state.json` now also records the widget's size (on resize and at exit), but nothing ever restores it. The main window is restored by the plugin as it is built (`on_window_ready`).
- **S4 `show_main` always runs on the main thread.** The tray menu calls it directly; the async `open_main` command and the single-instance callback (a zbus thread on Linux) go through `run_on_main_thread`. Building a window and reading its URL both need the main thread, and building one from a sync command deadlocks on Windows. The watch thread reads the main window's URL before it takes the navigation lock (the getter waits for the main thread, which may hold that lock); an epoch counter makes it skip a tick when `show_main` navigated in between, so a view asked for at the first open is never lost to a second navigation.
- **S5 Per-window navigation keeps `needs_navigate` as it was** (it already took the target). The main window's target is the prefix `http://127.0.0.1:<port>/`, so the hub page at any hash counts as "there" and is never reloaded; the widget keeps `/widget`. `show_main` treats "on the hub page" as `!needs_navigate(true, navigated, url, target)`. A view asked for before that is kept as pending and taken by the first navigation: `show_main`'s own if the hub answered at the last tick, else the watch thread's. A later open without a view keeps the pending one.
- **S6 `wants_main`:** the first argument starting `--open` decides; `--open=<view>` with an invalid view gives None (the widget, as the brief says), not the main window without a view. The whole argv is scanned; the program name can't match.
- **S7 The main window's 1440×900 is shrunk to the work area on its first build** (`fit_into_work_area`, tested), unless it was restored maximised. Not in the design: at 125 % a 1080p screen has 864 logical pixels of height. The window-state plugin's remembered size wins after that.
- **S8 The digest's starting pages are `../dist/<name>`**, relative to `src-tauri` like everything else (what Python's `os.path.relpath` gives), so they sort first. Without a `dist/` folder the digest is unchanged (the old vectors still hold); `SHELL_VECTOR_DIST` (`abd1a8ac…`) is shared by `test_update_step.py` and `shell_source.rs`. `build.rs` reruns on `../dist`.
- **S9 The starting pages** use a system mono stack (`ui-monospace, "DejaVu Sans Mono", "Cascadia Mono", Consolas, monospace`; Roboto lives with the hub). The main bar has the `line` rule (`#262626`) below it; the status text has a little tracking (.06em). The widget's bar shows the same amber dot and "STARTING THE HUB…" in mono 12 `#8a8a8a`, and uses `data-tauri-drag-region="deep"` (tauri 2.12's drag script supports it) so it still drags when pressed on the text or the dot. Both pass `tests/test_web_design.py`.
- **S10 `desktop-entry`:** `--exec` is required for `install` and optional for `status` (which then adds `current`: the entry and icon match that binary); it must be an executable file, made absolute without resolving links. `Exec` quoting follows the Desktop Entry spec: the path in double quotes with `"`, `` ` ``, `$` and `\` backslash-escaped, `%` doubled, then every backslash doubled again for the string level; a control character is refused. Files are written atomically and only when their bytes differ. Beyond the brief: `Version=1.5` and a `Comment`. The icon is copied from the running code's own `app/desktop/src-tauri/icons/128x128@2x.png` (in a runtime slot, that slot's). Exit codes: 0 done, 1 refused (missing exec, I/O), 2 usage or Windows.
- **S11 `StartupWMClass=atlas-desktop`:** tauri 2.12.4 creates its GTK application without an id (`app.enableGTKAppId` is off by default), so GTK's defaults name the X11 window class after the binary: `WM_CLASS = "atlas-desktop", "Atlas-desktop"`. Unchecked by hand: the owner confirms it with `xprop WM_CLASS`.

## Wave B: app shell
- **B1 The shell is a named-area grid** (`top`, `banner`, `view`, `tray`, `cap` in `css/app.css`), `html, body` at 100% with `overflow: hidden`. `#banner` and `#tray` are `display: none` while empty, so their rows take no height. The element ids `#banner #capture #tray #view #nav` stay; new ones are `#top`, `#brand`, `#mode`, `#status`, `#settings-tab`. The DOM order follows the grid (view, then tray, then capture). `<link rel="icon" href="data:,">` stops the favicon 404 from being the page's one console error.
- **B2 The top bar lives in `js/components/topbar.js`** (`mountTopbar({shell})` → `{render, refresh, setRoute}`); `app.js` keeps routing. Tabs are `a.tab[data-press]` (press.js gives them `.prs`), the selected one has `aria-current="page"` (components.css draws the underline). SETTINGS is `a.tab.set` with a left rule, min 132px (the arm's STOP width), the same underline when selected, `#141414` while pressed: never red. The brand is a link to `#/today` that inverts while pressed, as the arm's does.
- **B3 Fitting the bar is measured, not only a breakpoint.** When the tab strip would be cut, `topbar.js` first adds `.tight` (tab padding 14, cluster gap 12), then `.compact` (labels drop); if it is still cut the strip scrolls sideways with a hidden scrollbar and a 1px rule on its edge (`.ovf`), and the selected tab is scrolled into view. Below 1100px the labels always drop, as the brief says. Reason: with one chip showing, the full cluster doesn't fit even at 1280px. Re-fitted on a `ResizeObserver` of the bar and once the fonts load.
- **B4 Narrow forms:** REVIEW and VOICE lose their labels (the amber value and the switch stay, with titles); `5H`/`7D` keeps its window name, since it is the value's unit; the agents text becomes `2 · 1` (`2` without waiting). Chips never shorten.
- **B5 Status refresh:** `/api/widget` on `items.changed`, `agents.changed`, `usage.changed`, `filing.done`, `filing.failed`, `requests.changed`, `ws.open`, every 60 s, and every 5 s while offline (debounced 300 ms, like the widget); `/api/voice` on `voice.changed` (not during a download), `ws.open` and every 60 s. OFFLINE is a failed fetch with no HTTP status. `api.js` gains a `ws.close` event (once, when an open socket drops; not per retry) so OFFLINE shows at once instead of up to 60 s later. `opts.drive` is the shell's own `/api/state` drive.
- **B6 The VOICE switch is one persistent `switchEl({small: true, label: 'VOICE'})`** (so a refresh never steals focus), hidden until installed; its click is the widget's `toggleVoice` logic on `widgetVoice()`: resume a pause, else PUT `voice_enabled`. A paused voice shows the switch off. On a read-only root it is disabled with the reason as its title.
- **B7 Modes:** `mode()` is `reduced` (drive set and setup_done null), `setup` (setup not done) or `full`. Reduced: brand plus status-model's chips (`DRIVE`, `OFFLINE`), no tabs or SETTINGS, no `/api/widget` or `/api/voice` fetches; the view is one `notice()` titled `REDUCED MODE` with the drive message, the held count (`heldText`, else "Nothing held on this OS.") and a dim line that capture still works. The banner then leaves the drive line out (the notice says it). Setup: brand and a `SETUP` label only.
- **B8 The banner:** a connection error is a `.bn.err` line (`#ff6a5c`); the drive line (read-only) is a `.bn` with the amber square; the raw-log problem and startup problems are `notice()` panels (titles `RAW LOG`, `STARTUP`; the problems as mono dim list lines); time-zone and hibernation warnings are faint `.bn.q` lines. The banner scrolls inside itself past 30vh.
- **B9 Capture bar:** `CAPTURE` label, textarea, `.msg` (mono 12: the status, or the error in `#ff6a5c`), `SAVE` primary (min 112px). The textarea's height is its `rows` attribute (works in WebKitGTK, needs no inline style): 1 at rest; focused or holding text, at least 3 and as many as the content needs up to 6, then it scrolls. The bar has `.on` while active. Items align to the bottom, so SAVE stays where it was as the box grows. The behaviour is unchanged (text cleared only once the server has it, held captures, Ctrl+Enter); the failed-filing status now says "see the card above", since the tray sits above the bar.
- **B10 Keyboard:** Alt+1…6 and Alt+0 by `KeyboardEvent.code` (`Digit<n>`, layout independent), Alt+C by `code === 'KeyC'`; only with Alt and without Ctrl or Meta, so AltGr (Ctrl+Alt on Windows) still types ș ț ă î â. Tab keys only in full mode; Alt+C works in every mode.
- **B11 Routes:** `#/browse` renders the last-used browse page in place (the hash stays `#/browse`, BROWSE lit): `localStorage['atlas.browse']` (try/catch), written on every visit to `deadlines`, `people` or `project/<slug>` and only when `browseTarget()` accepts it. `#/settings/<section>` renders Settings and, for a section that has a heading id (`tablet`, `voice`), scrolls to it; an unknown section is just Settings. `usage` lights AGENTS. `#view` is scrolled to the top on every route.
- **B12 Interim legacy block** (end of `app.css`, to delete in wave C): un-restyled views (anything in `#view` without a `.vw` root) get 24px side margins, and their old bare/`primary` buttons, plus those of the confirm card in the tray, get a hairline outline so they stay findable. Wave C views opt out simply by rendering a `.vw` root.
- **B13 Layout hooks for the views** (in `app.css`): `.vw` is a view's root (it flows and `#view` scrolls it); `.vw.split` fills the view's height with columns that scroll on their own: `.rail` (240px, components.css), `.main` (the rest) and `.side` (360px, rule on its left; `.side.w400`). `.pane` is the 20/24px padding; `.actbar` a 72px action bar (`.grow` spacer inside). Each view's own rules go in `css/views/<view>.css` (one file per wave C agent: today, ask, journal, browse, agents, tablet, settings, setup).

## Wave C: widget
- **C5-1 Widget-only class names.** `widget.html` links `css/tokens.css`, `base.css`, `components.css`, then `widget.css`; the widget's own layout uses `w`-prefixed names (`.wpanel .wbar .wgrip .watt .wsyn .wcap .wstat .wgrid .wtile .wpop .wrow …`) so nothing collides with components' `.panel`, `.row`, `.dot`, `.empty`. It borrows `.b` (with `.on`, `.h40`), `.lb`, `.m`, `.err` from components. `html` gets `color-scheme: normal` and a transparent background: base.css's dark scheme would paint the transparent Tauri window's canvas.
- **C5-2 The capture field is 40px through `#w .wcap`.** base.css sizes fields with `input:not([type=checkbox]):not([type=radio]):not([type=range])` (specificity 0,3,1), which beats any one-class rule, so components' `input.h40` (0,1,1) never wins either: the lead may want to look at that for the app.
- **C5-3 The flush grid:** each tile draws its own top and left hairline and the grid sits 1px left (clipped by the panel), so the first column's rule hides under the panel edge and a short last row (a custom `widget_tiles` list) leaves no stray lines. Tiles are 96px: label, mono 500 28px value, faint caption at the foot. A warning makes the value amber and puts the 6×6 square top right; the open tile is white with black text (its square stays amber). The arm's value is uppercased in CSS (`ON`/`OFF`), the model still says `on`/`off`.
- **C5-4 The voice glyph is an inline SVG speaker in `currentColor`** (built with `createElementNS`, fixed shapes, no data), not `widgetVoice().icon`'s emoji: waves when on, no waves in quiet hours (still on, so still inverted), crossed when off or paused. The button carries `aria-pressed` and `.on`; the toggle logic is unchanged.
- **C5-5 Native open:** `openPlan(name, view, invoke)` and `tauriInvoke(win)` in `widget-model.js` (tested). With the shell's `__TAURI__.core.invoke`, a view opens through `open_main({view})`; if that is absent or rejects, `POST /api/open {target:'app', view}` as before. The arm always posts `{target:'arm'}`. `TILE_VIEW.projects` is `browse`.
- **C5-6 Press feedback** is a page-level `pointerdown` that adds `.prs` to `.b`, `.wtile` and `button.wrow` (the widget doesn't load press.js, which needs the app's live region); the opacity fade on expand is gone (no motion).
- **C5-7 OFFLINE shows at once:** the widget now refreshes on `ws.close` too (api.js, B5), instead of waiting up to 60 s for the next tick.

## Wave C: Ask and Journal
- **C2-1 The shared text pieces are styled in `css/views/journal.css`** (linked globally): the entry card `.ecard`, the hit list `.hitl`/`.hit`, citations `a.cite` and note text `.note-x`. Ask, Journal and Browse all draw them from `components/text.js`. The card's class is `ecard`, not the old `entry`, because the tablet view also renders `.entry`.
- **C2-2 `entryCard(e, {highlight, withDate})`:** a mono time column, the verbatim text in `.read` (whitespace kept), the synopsis in dim 14px, then a mono 12 dim line: the source, the filing status and the files. The status reads: an amber `FILING FAILED` chip and the error in `#ff6a5c` mono below it; a grey dot and `FILING` while queued or running; a faint `NOT FILED` with no filing (tablet notes); a faint `FILED · NO NOTES` when the filing touched no file; nothing else when it filed notes. `withDate` defaults to true, for lists without day headers (Browse): the column is 96px with the date above the time. Journal passes `false` to get the 64px time-only column. Every card has a 1px black border, so the white `?entry=` border shifts nothing. New pure helpers, all tested: `filingFiles`, `tsParts`, `filingState`, plus `noteText(text)` for a note opened in a viewer.
- **C2-3 `hitList(hits, onNote)` keeps its signature.** Each hit is one row: `ENTRY`/`NOTE` (faint), the date and the ref in mono 12 dim, then the snippet in dim 14px with its matches in white 600. An entry hit is a whole-row link to `#/journal?entry=`; a note hit is a button. Every row has `data-ref`, so Ask marks the note open in its viewer as `.cur` (inverted). No hits gives one faint `.empty` row.
- **C2-4 The Ask layout:** a query bar (a 56px field at 17px, plus a 56px primary `ASK`); below it a nested `.vw.split` with a 360px `.rail.ask-rail` (MATCHES with a mono count) and `.main`. The rail stays 360px at 900px too (the answer still gets 540px). Before the first question the rail shows one faint row and the answer pane a faint hint. The stream's state is in the ANSWER section header's right: a grey dot with `SEARCHING`, a green one with `THINKING` and then `STREAMING`, a grey one with `DONE`, and nothing after an error. `DIG DEEPER` (amber outline) and its faint cost note appear once the answer is done. DEEPER SEARCH gets its own header, status, error line and `RETRY`, so a failed dig no longer puts its error above the first answer. Pressing DIG DEEPER removes the button, as before.

## Review fixes: shell
- **R-S1 A window is never built inside a sent message.** In tauri-runtime-wry 2.12.2, `send_user_message` runs a `run_on_main_thread` task inline when it is called on the main thread. On Windows, tauri-plugin-single-instance 2.5.4 calls its callback from its window's WM_COPYDATA procedure, which runs on the main thread inside a message sent by the second process. So `open_main_later` now always posts from a new thread (`std::thread::spawn`, then `run_on_main_thread`), and `show_main` runs after that message has returned. The tray's "Open ATLAS" still calls `show_main` directly: muda's handler only forwards the event to the event loop (tauri 2.12.4 `app.rs`), so it never runs inside a sent message. The async `open_main` command runs on the async runtime, so its post is never inline.
- **R-S2 A failed load is loaded again; a page that loaded is still never reloaded.** WebKitGTK (`load-changed` FINISHED after `load-failed`) and WebView2 (`NavigationCompleted`) both report a failed load as finished, at the URL that failed, so the URL alone can't tell the "could not connect" page from the hub page. Each window now has a state, `Page::Start | Loading(since) | Loaded`, tested in `next_step` and `after_load`. Both windows get `on_page_load`: a load that finishes at the hub's URL asks the port off the main thread (`supervisor::hub_up`, 500 ms), then settles the state on the main thread. If the hub answered, the state becomes `Loaded`. If it didn't, it goes back to `Start`, and the next tick navigates once the hub is up. The main window keeps the failed URL's view (`view_in`). After a failure, a finished load stays `Start`: it is the error page's own load or a stale event. A counter bumped by every navigation drops results that a newer navigation overtook. A load whose URL still isn't the hub's after 20 s (`LOAD_GRACE`) is tried again. The page is never asked anything, so the main window still has no IPC. Residuals: a page that reloads itself (F5) while the hub is down is caught the same way. A page that loaded during the 500 ms in which the hub stopped is reloaded once, before anyone could type in it. If the hub comes back within milliseconds of a failed load, that load may still count as loaded.
- **R-S3 S7 is now computed before the build:** `WebviewWindowBuilder::prevent_overflow_with_margin` (tauri 2.12.4) shrinks the requested 1440×900 to the primary monitor's work area, scale-aware, while the window is created (the same monitor `.center()` uses). On Linux, tao caches size and position until GTK's configure events, so measuring the unmapped window did nothing. On Linux the margin is 0×40 logical px, for KWin's title bar, which tauri counts only on Windows; on Windows it is 0×0. The window-state plugin's `on_window_ready` restore runs after that, so a remembered size or maximised state still wins. `fit_into_work_area` and `fit_on_screen` are gone; `keep_on_screen` still runs after the build.
- **R-S4 All navigation state lives on the main thread.** The watch thread only stores `up` and posts `steer` with `run_on_main_thread`, so it never waits for the main thread. `show_main`, `steer` and `load_settled` run there one after another, so a view asked for can't be lost to the tick's navigation to `/`. The epoch counter is gone. A view asked for while a load is under way is kept as pending, and its hash is set once that load has finished (`load_settled`); the load isn't restarted. The navigation counter is an atomic outside the lock, so the web view callback never waits for a lock.
- **R-S5 `StartupNotify=false`** in the launcher entry. The usual click is a second launch: the shell is already running from autostart, so the click hands `--open` over and exits before any window of its own. That never completes a startup notification, so `true` left a busy cursor until the desktop's timeout. An entry installed earlier reads `current: false` in `status` until `install` is run again.
- **R-S6 `open_main` returns `Result<(), String>`.** It is an error when `show_main` couldn't show the window (no managed state, the build failed, `show()` failed) or no answer came within 5 s. The command waits on a channel in `spawn_blocking`. The widget runs the invoke through `openOutcome` (`widget-model.js`, tested): `'shell'` when it resolves; `'fallback'` when it rejects, throws or doesn't settle within `OPEN_MAIN_TIMEOUT_MS` (3 s). On fallback it posts `/api/open`. If the shell answers after the widget gave up, both the main window and the browser open; that was accepted as rare.
- **R-S7 Launch arguments are read with `std::env::args_os()`, converted lossily**: `std::env::args()` panics in setup on an argument that isn't UTF-8. A lossy `--open=…` can only fail `valid_view`.
- **R-S8 `tail.map_or(true, …)` became `tail.is_none_or(…)`** (stable since Rust 1.82; the toolchain is 1.99, and `Cargo.toml` sets no `rust-version`). `cargo clippy --all-targets -D warnings` is clean too: a test's `&vec![…]` became an owned `Vec` built from a slice.
- **R-S9 The widget's agents popup meta leaves out an "unknown" Where** (no entrypoint seen, `agents.WHERE_CHOICES`) **and empty or blank parts**. "waiting · unknown · next time" now reads "waiting · next time".
