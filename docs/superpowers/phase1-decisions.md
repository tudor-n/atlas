# Phase 1 build decisions

These are the decisions taken during the autonomous build of phase 1 (2026-10-20/21) where the plan was silent, wrong, or in conflict with the spec. Each one says why it was made and what it costs if wrong. The spec stays the authority.

## Rulings
- Ruling 1: The filing agent runs in an isolated **git worktree** of brain (`data/worktrees/<entry_id>`, detached at main HEAD after committing dirty state). The protected-path check and restore happen in the worktree; the agent's work is committed there and **cherry-picked** onto brain's main branch. The worktree is always removed (in a finally). A cherry-pick conflict means `cherry-pick --abort` and a failed filing with the error "conflict with concurrent edits — retry". BrainRepo gains `worktree_add(path) -> BrainRepo`, `worktree_remove(path)`, `cherry_pick(sha) -> str | None` and `changed_files(sha) -> list[str]`. — Why: in the plan as written, a capture appended to the raw log while an agent ran would be reverted by `restore_paths(["log"])` (verbatim log loss), and a confirm's commit during a run would swallow the agent's partial edits. This violates the spec §4 raw-log guarantee. — Cost if wrong: more git plumbing than needed; it is contained in gitrepo.py and filing.py.
- Ruling 2: BrainRepo serialises all git operations on one repo with an internal `threading.Lock` (the worker, reviewer, backup and server call from different threads). — Why: git index.lock collisions. — Cost if wrong: negligible.
- Ruling 3: The `proposals` and `filings` tables do not enforce foreign keys to `entries`. — Why: the T5/T9 tests create proposals for entry "e-1" with no entry row. — Cost if wrong: an orphan row is possible, harmless.
- Ruling 4: Reviewer exposes `paths`, `store`, `repo` as public attributes (T9 fixture uses them). — Cost if wrong: none.
- Ruling 5: `FakeRepo` and `Clock` test doubles live in `tests/fakes.py` (created in T10, reused by T14's test_server). — Cost if wrong: none.
- Ruling 6: The T15 e2e runs against a **scratch root** (`D:\BrainHub-e2e`, removed afterwards) with a plausible map (robotarm, tracegreen, vibedine, hackathon, plus courses and people), NOT against `D:\BrainHub\brain`. The owner runs the real setup wizard themselves. — Why: the owner hasn't given the full map (which project is the company, courses, teammates); a guessed real brain would pre-empt their wizard. — Cost if wrong: the owner spends 2 minutes in the wizard, which was intended anyway.
- Ruling 7: commit_all keeps `None` for "nothing to commit" (brief contract) but raises RuntimeError on real failure; restore_paths/discard_changes/init raise on failure — brief's silence on failure isn't a mandate to swallow errors — cost if wrong: callers must handle exceptions (Task 7 already wraps in try).
- Ruling 8: Task 7 fix may edit gitrepo.py (changed_files -z) — root cause in Task 3 code breaks Task 7 reindex — cost if wrong: none.
- Ruling 9: Today `upcoming` excludes items already in overdue/due_today (only due date > today with remind_at <= now) — spec "no clutter"/anti-goal outranks plan's literal `remind_at <= now < due` — cost if wrong: an item due later today with a reminder shows only once (under due_today).
- Ruling 10: Reviewer.confirm marks each proposal confirmed immediately after its own apply step; export/commit failure propagates with SQLite consistent and next commit sweeping files — avoids duplicate items on retry — cost if wrong: a failed commit leaves files uncommitted until next commit.
- Ruling 11: confirm auto-includes same-entry pending node proposals referenced by selected items, and skips (no-op confirm) nodes whose slug already exists — filing pipeline routinely produces item+node pairs; per-row ✓ must not error — cost if wrong: a node gets created when owner ticked only the item that names it (that's what the item implies anyway).
- Ruling 12: server startup never crashes on a damaged/truncated raw log or failed reindex: logs it, keeps serving, exposes `log_error` in /api/state, never auto-modifies the log — addresses Task 4 deferred SHOULD-FIX — cost if wrong: owner must fix the log file by hand (surfaced in UI).
- Ruling 13: Task 11 fix may edit rawlog.py (module-level threading.Lock around append) and filing.py (mark_queued split) — root causes live there — cost if wrong: none.
- Ruling 14: strengthen the plan's test_search_endpoint_returns_hits_without_claude (assert 200 + ref + no Claude call, blank q behaviour) — plan text mandated a test that asserts nothing meaningful — cost if wrong: none.
- Ruling 15: Task 14 fix may edit brainmap.py (reserved slugs in validate_map — also resolves Task 2 deferred SHOULD-FIX), config.py (backup_remote URL validation, non-empty claude_path/models) and gitrepo.py (--end-of-options) — cost if wrong: a legit unusual remote URL format (e.g. file path) is rejected; owner can extend the regex.
- Ruling F1: on rebuild, entries with a `file <id>:` commit in brain history are marked done (not re-filed); pending proposals persisted to brain/_items/proposals.json; >10 unfiled entries at startup become failed-with-Retry instead of auto-queued — avoids mass re-filing/duplicate notes/usage burn — cost if wrong: owner presses Retry on some genuinely unfiled entries.
- Ruling F2: Today places by due-or-remind_at plus a catch-all "Other open items" section — nothing confirmed may vanish — cost if wrong: one more section on Today.
- Ruling F3: reindex changed .md after every hub commit + always rebuild notes index at startup; skip dot-folders; per-file errors=replace — recall must never quote stale text — cost if wrong: a few hundred ms extra at startup.
- Ruling F4..F12: as written in final-fix-wave.md (push outside repo lock w/ non-interactive creds + 120s timeout; .gitattributes `* -text`; --tools explicit + strict MCP + no session persistence (setting-sources only if login verified); existing slugs read-only + server refuses removing/renaming slugs with content; slugify area/parent, node order, course-as-project, card person/area editors; validate remote before setup writes; startup_error + stale index.lock removal + atomic settings; /api/filings?status=failed; journal area filter).

## Known residuals (parked after the final review)
- reverted filing commit still counts as landed (Retry after failed correction tells agent "still in notes"; rebuild could mark reverted-never-refiled entry done) — Ruling: real, deferred; needs `commit=None` after successful revert; rare path (correction + re-file failure + Retry) — cost if wrong: a correction's text could be dropped on that path.
- protected-path restore fails when mixing tracked + brand-new paths (e.g. agent edits _items + creates .claude/) → filing fails safely, Retry needed — Ruling: deferred; fail-safe, no data loss — cost if wrong: occasional manual Retry.
- _open_store catches all sqlite3.DatabaseError (could move aside a busy-but-healthy db) — Ruling: deferred; rebuild is now safe (C1) so worst case is a rebuild — cost: a slower startup.
- proposals.json written in place without lock — Ruling: deferred; self-heals next export, matters only if db lost in that window — cost: restore reports file damaged.
- failed restore of corrupt items/proposals json gets overwritten by next export — Ruling: deferred; data remains in git history — cost: owner recovers via git.
- queue step runs even if history recovery failed (≤10 rebuild entries could re-file) — Ruling: deferred; needs a git failure during rebuild — cost: duplicate note text on that path.
